# mw-metabolite-network

Cross-study metabolite correlation network, built from Metabolomics
Workbench (MW) data: download studies, correlate metabolite pairs within
each study, pool those correlations across studies (Fisher's z), keep only
statistically robust pairs as edges, and cluster the resulting network with
per-cluster KEGG pathway enrichment.

Branch `nafld` adds two things on top of that core network:

- a **NAFLD analysis** (`nafld_analysis/`, plus notebooks): per-study Kendall
  tau of every metabolite against a NAFLD label, a subgraph of the core
  network restricted to the tested metabolites, and spatial-autocorrelation /
  enrichment analyses over it.
- a **second, independent network from MetaboLights** (`src/metabolights/`,
  `scripts/metabolights_*`), built with the same correlate -> pool -> graph
  machinery but keyed by ChEBI accession instead of RefMet id. It exists to
  cross-check the MW network: 1,289 nodes and ~54k edges are shared between
  the two, pooled from disjoint sets of studies.

## Setup

```
pip install -r requirements.txt
# or, to also get `mwnetwork` importable as a package:
pip install -e .
```

Every script under `scripts/` also works without an editable install --
each inserts `src/` onto `sys.path` itself.

## Prerequisite data (already included under `data/`)

- `data/refmet.csv` -- local snapshot of MW's RefMet database (~200k rows,
  `refmet_id`/`refmet_name`/`super_class`/... columns). Used for local
  name -> ID lookup and, later, network node annotation.
- `data/metabolomics_workbench/human_blood_studies.csv` -- the selected MW
  study ID list to download (index = MW `study_id`).
- `data/metabolights/metabolights_studies.tsv` -- the full MetaboLights study
  catalog (3,503 rows x 109 columns), exported from the EBI study-search
  service. Only needed for the MetaboLights pipeline. No script in this repo
  produces it; it is a manual export, so a refresh will silently move the
  study selection.

Everything else (checkpoints, correlation tables, the network itself) is
generated by the pipeline below into `checkpoints/`, which is gitignored.

## Pipeline

Three stages, in dependency order. The NAFLD analysis needs the MW core graph
from stage A; the MetaboLights pipeline is independent of both and can run on
its own.

**A. MW core network**

```
python scripts/01_download_studies.py --all --overwrite
python scripts/02_compute_correlations.py --all --overwrite --pqn
python scripts/03_concat_correlations.py
python scripts/04_pool_correlations.py --methods pearson spearman
python scripts/05_build_network.py
python scripts/06_cluster_and_enrich.py --n-clusters 30
```

**B. NAFLD analysis** (needs A)

```
python nafld_analysis/run_kendall_correlations.py
python nafld_analysis/build_nafld_subgraph.py
python nafld_analysis/build_nafld_network.py
python nafld_analysis/build_nafld_significant_subgraph.py \
    --alpha 0.05 --min-n 10 --fdr-scope dataset
python nafld_analysis/build_nafld_network.py \
    --output-dir checkpoints/metabolomics_workbench/nafld_subgraph_significant
# then: nafld_spatial_autocorrelation.ipynb
#       nafld_spatial_autocorrelation_per_study.ipynb
#       signal_regression.ipynb
```

**C. MetaboLights network** (independent)

```
python scripts/metabolights_01_download_studies.py --all
python scripts/metabolights_02_compute_correlations.py --all --overwrite
python scripts/metabolights_03_concat_correlations.py
python scripts/metabolights_04_pool_correlations.py \
    --methods pearson spearman --min-studies 4
python scripts/metabolights_05_build_network.py
```

## A. MW core network

### A1. Download + standardize study data -- `01_download_studies.py`

For each study in `human_blood_studies.csv`: fetches every analysis via the
MW REST API + `mwtab`, keeps only analyses with a standardized
quantification block (`MS_METABOLITE_DATA` / `NMR_METABOLITE_DATA`),
standardizes metabolite column names to RefMet (local `refmet.csv` lookup,
falling back to MW's live `refmet/match` API for names the local snapshot
misses), then merges all analyses of a study into one samples x metabolites
CSV (outer join on samples/metabolites).

- `-n N` : only try the first N studies (test run, default 5)
- `--all` : run on every study in the CSV
- `--random --seed S` : sample N studies randomly instead
- `--join inner` : keep only samples common to every analysis of a study
  (default `outer`: union, NaN where missing)

Writes `checkpoints/metabolomics_workbench/studies/{STUDY_ID}_combined.csv`
plus disk caches under `checkpoints/metabolomics_workbench/.cache/` so
re-runs don't re-hit the API for names/analyses already resolved.

Names neither locally nor MW-resolvable to a RefMet ID are kept as their
bare name, prefixed `UNMAPPED:` (never silently relabeled).

### A2. Per-study pairwise correlations -- `02_compute_correlations.py`

For each downloaded study, computes pairwise metabolite correlations
(pearson/spearman vectorized via `df.corr()` + a t-distribution p-value;
kendall via a per-pair scipy loop) and writes one long-format Parquet file
per study x method (upper-triangle of the correlation matrix,
`metabolite_1`/`metabolite_2` alphabetically sorted so the same pair is
labeled identically regardless of a study's column order).

- `--methods pearson spearman kendall` : which methods to compute (default
  `pearson spearman`)
- `--transform log|sqrt|none` : value transform applied before correlating
  (default `log`)
- `--pqn` : apply PQN row-normalization before the transform (default: off)
- `--keep-unmapped` : keep `UNMAPPED:` columns (default: dropped)

Writes `checkpoints/metabolomics_workbench/correlations/{STUDY_ID}_{method}.parquet`.

### A3. Concatenate across studies -- `03_concat_correlations.py`

Concatenates all per-study Parquet files into one combined long-format file
per method, sorted by `(metabolite_1, metabolite_2)`.

Writes `checkpoints/metabolomics_workbench/correlations_combined/{method}.parquet`.

### A4. Cross-study meta-analysis -- `04_pool_correlations.py`

Pools each metabolite pair's per-study `(r, n)` via inverse-variance
weighted Fisher's z meta-analysis (`mwnetwork.meta_analysis.pool_correlations`
-- fixed-effect + DerSimonian-Laird random-effect estimate, heterogeneity
stats Q/I2). Only pairs seen in `--min-studies` studies or more are pooled
(default 4).

Rows are filtered before grouping: the NAFLD cohorts
(`nafld_labels.NAFLD_STUDY_IDS`) are held out so the core network stays a
disease-free scaffold for stage B, plus `n > 3` (Fisher z variance 1/(n-3) is
undefined below that), non-null `p_value`, and both labels matching the id
pattern.

- `--limit N` : only pool the first N eligible pairs (test run)
- `--overwrite` : ignore/replace any existing pooled output instead of
  resuming from it
- `--min-studies N` : minimum studies per pair (default 4)

`pool_method` also takes `id_pattern` and `exclude_studies` as keyword
arguments (defaulting to the RefMet id pattern and the NAFLD hold-out), which
is what lets the MetaboLights pipeline in stage C reuse it unchanged.

Writes `checkpoints/metabolomics_workbench/correlations_combined/{method}_pooled.parquet`.

### A5. Build the network -- `05_build_network.py`

Keeps only CI-significant pooled edges (random-effect CI doesn't cross 0),
builds an `nx.Graph`, annotates nodes from `data/refmet.csv`
(super_class/main_class/sub_class/formula), lays it out with a
dijkstra-shortest-path distance matrix + TSNE embedding, and exports an
interactive plotly HTML viewer with legend-driven edge filtering
(`src/mwnetwork/assets/edge_filter.js`).

Three independent distance scenarios (`--scenarios abs signed posonly`,
default: all three) -- see the docstring in `src/mwnetwork/network.py` for
what each one means and why.

Writes, per scenario, `checkpoints/metabolomics_workbench/core_graph/{graph_distances,embedding,viewer}<suffix>.csv|.html`,
plus once (independent of scenario) `edges.parquet` / `nodes.parquet`.

> **Note on node annotation:** the original exploratory workflow used a
> richer `refmet_harmonized.csv` (cross-referencing ChEBI/KEGG/PubChem for
> metabolites RefMet itself doesn't classify), built by a one-off
> harmonization script that was never committed anywhere retrievable. This
> package uses the plain `data/refmet.csv` instead, which already carries
> `super_class`/`main_class`/`sub_class`/`formula` for every node the
> network plot actually uses. If you rebuild that enrichment step yourself,
> point `network.annotate_and_save_graph`'s `refmet_path` at it instead.

### A6. Cluster + enrich -- `06_cluster_and_enrich.py`

Hierarchical (ward) clustering of the `posonly` scenario's node-node graph
distance matrix into `--n-clusters` groups, a dendrogram plot showing each
cluster's `super_class` composition, and per-cluster KEGG pathway
over-representation (hypergeometric test against the whole graph's KEGG
IDs as background) via `src/mwnetwork/kegg_enrichment.py`. RefMet
cross-references (kegg_id, etc.) are fetched live per node from MW's REST
API and disk-cached.

Writes `checkpoints/metabolomics_workbench/core_graph/cluster_dendrogram.html`
and prints each cluster's significant (`padj < 0.05`) pathways.

## B. NAFLD analysis (`nafld_analysis/`)

Built on top of the MW core network. The NAFLD study ids and label
definitions live in `src/mwnetwork/nafld_labels.py`; those studies are
**excluded** from the core network's pooling (`mwnetwork.pool`), so the core
graph stays a disease-free scaffold and the NAFLD signal is measured against
it rather than inside it.

### B1. Per-study metabolite-vs-label association -- `run_kendall_correlations.py`

Kendall tau-b of every RefMet-standardized metabolite against each NAFLD
label contrast, per study, from the `{STUDY_ID}_combined.csv` tables of step
1. No arguments. Writes one CSV per (study, label) into
`checkpoints/metabolomics_workbench/nafld_analysis/`.

### B2. NAFLD subgraph -- `build_nafld_subgraph.py`

The core graph induced on the metabolites that were tested against a NAFLD
label, with each node carrying a weighted tau aggregated across the studies
that tested it. Edges remain the core network's pooled edges -- they are not
recomputed from NAFLD data. No arguments. Writes
`checkpoints/metabolomics_workbench/nafld_subgraph/`.

### B3. Significance-filtered subgraph -- `build_nafld_significant_subgraph.py`

The same construction restricted to associations that survive a
Benjamini-Hochberg correction, as a sensitivity analysis.

- `--alpha 0.05` : BH cutoff on q
- `--min-n 10` : drop association rows with fewer paired observations.
  Applied *before* the correction, because those rows are excluded a priori
  for insufficient data (n depends on measurement coverage, not on the
  realized tau), so dropping them is not selection on the outcome.
- `--fdr-scope dataset` : BH family is one (study, label) contrast. `global`
  pools every row into a single family, which is **not** uniformly stricter --
  a study with many tests gets diluted by its own family under `dataset`.

Writes `checkpoints/metabolomics_workbench/nafld_subgraph_significant/`, kept
separate so the unfiltered subgraph and everything derived from it are
untouched. Results: 665 of 2,035 testable rows, 482 of 548 metabolites in the
core graph, density 0.339 vs 0.049 unfiltered.

> Filtering on the tau p-value is selection on the outcome, and the
> detectable |tau| moves with n (n=10 needs 0.487, n=517 needs 0.058), so the
> effective threshold tracks study membership. This subgraph is a robustness
> check, not the primary signal.

### B4. Viewer export -- `build_nafld_network.py`

Per-scenario graph distances, embedding and interactive HTML for a subgraph
directory. Run once per subgraph:

- `--output-dir` : which subgraph to export (default: the unfiltered one).
  A directory containing `associations.csv` ships that filtered subset, and
  the viewer's dataset checkboxes then offer exactly the contrasts that
  backed each node's tau.
- `--scenarios abs signed posonly` : default all three.

### B5. Notebooks

- `nafld_spatial_autocorrelation.ipynb` -- global Moran's I and LISA over the
  subgraph, under both a free permutation null and one restricted within
  `super_class`. The restricted null is the one to read: on the full node set
  the global z falls from +40.65 to **+2.59** once chemical class is held
  fixed, so most of the free-null signal is class structure.
- `nafld_spatial_autocorrelation_per_study.ipynb` -- the same per study.
  ST001843 and ST001842 survive the restricted null; ST002091 collapses
  (z +30.70 -> +0.74) on only 3 super_classes.
- `signal_regression.ipynb` -- signal propagation / regression over the graph.

Permutation machinery is in `utils/spatial_autocorrelation.py`. Note that a
permutation p cannot fall below `1/(N_PERM+1)`, so with `N_PERM=199` a LISA
over 482 nodes cannot call anything at all under BH; these ran at
`N_PERM=9999`.

## C. MetaboLights network (`src/metabolights/`, `scripts/metabolights_*`)

Same correlate -> concat -> pool -> graph machinery as A, with three
differences that drive the whole design:

1. **A study is not one table.** MW merges a study's analyses at download
   time; a MetaboLights study publishes up to 14 metabolite assignment files
   (MAFs), and 134 of 266 have more than one. Merging them is its own stage
   (`metabolights.combine`).
2. **The cross-study key is ChEBI**, taken from the MAF's
   `database_identifier`, not RefMet. Features carrying neither a ChEBI
   accession nor an InChI are dropped at download; the combine stage then
   needs ChEBI specifically, so InChI-only features are lost there
   (43,749 features across 42 studies -- see the caveat below).
3. **Dilution normalization happens per MAF**, inside the merge, not over the
   merged table. See C2.

### C1. Select + download -- `metabolights_01_download_studies.py`

Selects studies from the catalog and downloads their ISA-Tab archives from
the EBI public FTP mirror, then parses each into one samples table plus a
metabolites/matrix pair per MAF.

- `--all` : every selected study (414 with the defaults below)
- `--organism "Homo sapiens"` and `--organism-parts plasma serum blood
  "blood plasma" "blood serum" "venous blood" "whole blood" "peripheral
  blood"` : the selection, reproducing the EBI faceted search plus three
  extra blood spellings. Terms are matched **exactly** against the
  `"; "`-joined `organismParts.term` list, so `serum` does not also take
  `fetal bovine serum`.
- `--keep-unlinkable` : keep features with neither a ChEBI id nor an InChI
  (default: dropped)
- `--keep-replicates` : keep abundance columns that map to the same sample
  (default: averaged, nan-aware)
- `--dry-run`, `--study-ids`, `--overwrite`

Writes `checkpoints/metabolights/raw/{STUDY_ID}/` (the download cache -- a
file already present is never re-fetched) and
`checkpoints/metabolights/studies/{STUDY_ID}/`.

Results: 414 selected, **264 written, 8 failed, 142 with no usable MAF**. Of
the 8 failures, 5 are non-UTF-8 ISA files, 1 a ragged table, and 2 publish no
ISA-Tab at all. The 142 are mostly studies whose MAF carries identifications
with an empty abundance block.

### C2. Merge to ChEBI + correlate -- `metabolights_02_compute_correlations.py`

Two stages in one script. First `metabolights.combine` maps each MAF's
features to `CHEBI:<n>`, transposes to samples x ChEBI, averages features
sharing an accession (204 MAFs have such collisions), applies PQN per MAF,
merges a study's MAFs on the union of their samples, and drops samples left
with no values. Then `mwnetwork.correlate` runs unchanged over the result --
the merged tables are written as `{STUDY_ID}_combined.csv` indexed by
`sample_id`, deliberately the same shape the MW pipeline produces.

- `--no-pqn` : skip dilution normalization
- `--skip-combine` : reuse existing merged tables
- `--methods pearson spearman`, `--transform log`, `--min-unique-values 3`
- `--keep-mw-duplicates` : keep cohorts also deposited in MW. By default
  `MTBLS7776` (= `ST002764`) and `MTBLS3305` (= `ST001933`) are dropped --
  the same subjects published twice would be counted twice by any pooling
  that treats the two sources as independent.

> **PQN must be applied per MAF, which is why it moved out of
> `correlate.load_combined_study` for this pipeline.** PQN derives each
> sample's dilution factor from its row sum, which assumes every sample
> measured the same metabolites. A merged multi-MAF table breaks that: on
> MTBLS13090 (two CE-MS polarities over different samples) PQN over the
> merged table produced per-sample factors spanning 0.0183 to 1410 and lifted
> median |r| from 0.174 to 0.807 -- manufactured correlation. Per MAF, with
> empty samples dropped, the same study gives 0.387.

### C3-C4. Concat + pool -- `metabolights_03/04_*.py`

Identical to A3/A4. Concatenation is still required: that stage concatenates
per-study *correlation* files, not data tables, and is what `pool_method`
reads.

`metabolights_04_pool_correlations.py` differs from the MW run in two
arguments: the id pattern is `^CHEBI:\d+$`, and `--exclude-studies` is empty
by default (the MW run holds the NAFLD cohorts out of its core network;
MTBLS174 / MTBLS298 / MTBLS616 / MTBLS2615 are the MetaboLights equivalents
if that hold-out is ever wanted).

- `--min-studies 4` : as in A
- `--limit`, `--overwrite`, `--exclude-studies`

### C5. Build the network -- `metabolights_05_build_network.py`

`mwnetwork.network.build_network` over the ChEBI-keyed pooled file, with node
annotation from `data/refmet.csv` re-indexed by ChEBI accession
(`metabolights.network.refmet_by_chebi`). Hover and search carry both the
ChEBI label and the mapped RefMet id.

- `--method pearson` (default) or `spearman`
- `--scenarios abs signed posonly`, `--output-dir`

Writes `checkpoints/metabolights/core_graph/`.

### Known limits of the MetaboLights network

- **Annotation coverage.** 1,657 of 2,183 nodes (75.9%) map to a RefMet row;
  `kegg_id` reaches only 48.2%, which is the binding constraint on any KEGG
  enrichment here. 60 nodes had a competing RefMet row discarded (ChEBI is
  coarser than RefMet), and for 8 of those the discarded row had a different
  `super_class`. The 526 unannotated nodes are present in `nodes.parquet` as
  all-NaN rows, so a consumer must treat a missing `super_class` as "unknown"
  rather than relying on a `dict.get` default -- see `network.node_table`.
- **Evidence per study is much thinner than MW's**: median per-pair n is 6
  against MW's 73, and over half the study-level observations have n <= 10,
  where the Fisher-z variance 1/(n-3) makes them nearly uninformative. They
  still count toward `--min-studies`.
- **Heterogeneity is high**: median `tau2` 0.296 against MW's 0.050, and
  median `se_random` 0.189 against MW's 0.087. So `r_random` is the only
  defensible estimate, and the dijkstra scenarios inherit that across hops.
  Judge this by `tau2`/`se_random`, not by I2 (97.5% here vs 89.0% for MW):
  I2 = (Q-df)/Q scales between-study spread by within-study variance, so it
  rises with per-study n at unchanged tau2 and cannot be compared across
  sources with different per-study precision.
- **InChI-only features are dropped** at the combine stage without a count
  (43,749 across 42 studies). Recovering them needs an InChI -> InChIKey ->
  RefMet -> ChEBI backfill.

## Scope

Stage A covers the reproducible core: MW download through the correlation
network and its cluster-level pathway enrichment. Two things from the
original exploratory work are intentionally left out as out of scope for a
from-scratch rebuild:

- the lost RefMet/ChEBI/KEGG/PubChem harmonization step (see the note in
  step A5 above)
- a disease-subset validation notebook (comparing study-specific vs. pooled
  global correlations for a hand-picked set of hepatic-disease studies) --
  a case-study built on top of this pipeline's outputs, not part of building
  the network itself

Not yet done on this branch:

- **Merging the two networks.** 1,289 RefMet ids and ~172k pooled pairs are
  shared between stage A and stage C, from disjoint sets of studies, so stage
  C is an independent replication set rather than extra data.

  Measured on those shared pairs (pearson, `r_random`), the two sources are
  **not** equally informative:

  | | tau2 (median) | se_random (median) | reliability |
  |---|---|---|---|
  | MW (stage A) | 0.037 | 0.051 | 0.629 |
  | MetaboLights (stage C) | 0.321 | 0.185 | **0.000** |

  Reliability is the fraction of the spread in `r_random` across pairs that is
  not accounted for by the estimates' own sampling variance. For stage C as a
  whole it is zero -- mean `se^2` (0.0705) exceeds the variance of the
  estimates (0.0619), so the pooled values carry no net signal above their own
  noise, and `r(ml, mw)` is only 0.29. That does not improve by filtering on
  per-study n, nor by PQN placement; both were tried.

  It *does* improve by gating on each pooled estimate's own precision, which
  is legitimate because `se_random` is independent of the realized `r` (the
  same argument that makes `--min-n` acceptable in B3 while p-filtering is
  not):

  | `se_random` cutoff | pairs | reliability | r(ml, mw) | disattenuated | tau2 |
  |---|---|---|---|---|---|
  | 0.20 | 94,376 | 0.693 | 0.442 | 0.642 | 0.091 |
  | **0.12** | **46,384** | **0.822** | **0.539** | **0.733** | **0.025** |
  | 0.08 | 23,230 | 0.850 | 0.518 | 0.726 | 0.009 |

  So roughly 46k pairs replicate well, with heterogeneity below MW's own.
  Any merge should therefore weight by precision rather than treat the two
  sources as equivalent:

  - *one-stage*: re-key the stage C rows to RefMet, concatenate both
    `{method}.parquet` study-level tables and run `pool_method` once, so every
    study is weighted by its own n-3 under a single tau2. Add a per-pair floor
    on the total Fisher weight each source contributes -- the study-level
    analogue of the `se_random` gate, since `se^2 ~ 1/sum(w) + tau2`. Without
    it, stage C's tau2 of 0.32 is pooled into a single shared tau2 and widens
    every CI in the merged network, including pairs MW alone estimated well.
  - *two-stage*: combine the two `r_random` values weighting by
    `1/se_random^2`, which is self-regulating (MW's median se gives it ~13x
    stage C's weight) but cannot estimate a between-source tau2 from two
    units, so it is a fixed-effect combination of two random-effects results.

  Note that **I2 is the wrong diagnostic here** and earlier readings of it
  were misleading: I2 = (Q-df)/Q compares between-study spread to within-study
  variance, so it rises as per-study n rises even when tau2 is unchanged.
  Stage C's I2 of ~98% alongside tau2 of 0.32 reflects both. Use tau2 and
  `se_random`.
- a KEGG backfill from `refmet_api_cache.json` (which covers 1,250 of the
  NAFLD subgraph's 1,341 nodes against `refmet.csv`'s 253)
- replacing `compute_weighted_tau`'s plain-n weighting with
  `loso.fisher_weight`, which disagree today on rows with n <= 4
